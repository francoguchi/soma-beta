## Binding choices and limits
- **D1:** Room `rack_count` and Cloud Deployment `assigned_network_element_count` include **all persisted current direct records**, including archived records. These are not active-only counts.
- **D2:** Two exact GET point reads (`rooms/{room_id}`, `cloud-deployments/{cloud_deployment_id}`) and one typed GET `related-children` limited to **four** direct relation families. Reuse original Explorer and RackOccupancy. No new mutation or speculative physical Cloud ownership.
- **D3:** Related-child UUID4 ascending keyset; at most 200 rows per page, default 100, `CURSOR_V1` exact six-field envelope and canonical fingerprint of `{parent_kind,parent_id,relationship,lifecycle:null|value,limit}` (limit bound). Each page uses a fresh stable `ReadSnapshot`; never claim cross-page snapshot pinning. Reuse existing indexes; never add an unallocated migration.
- **D4:** `INFRA_ROOM_DETAIL_QUERY_V1`, `INFRA_CLOUD_DEPLOYMENT_DETAIL_QUERY_V1`, `INFRA_RELATIONSHIP_CHILDREN_QUERY_V1` and exact matching response types. Fail on missing parent with `INFRA_NOT_FOUND`, stale/corrupt links with `INFRA_STALE`, malformed cursors with `CURSOR_INVALID`, invalid typed request with canonical LLD-08 validation errors.
- **Permissions:** LLD-12 local admin authenticated GET, no CSRF write path, no writer UoW/revisions/audit additions. Physical Room→Rack, Site→explicit unracked NE; logical Cloud assignment and direct containment are independent. Archive retrieval allowed. A cross-Site Cloud assignment is corrupt; direct cross-Site containment is not forbidden by existing schema.
- **Source/trust:** Current owner tables only; no synthetic historical facts, external Customer query or inferred children. Always fail closed for invalid parent identity/unknown query field/duplicate or unordered rows, unexpected response fields, missing active NE placement, or cross-Site Cloud assignment.
